مركز موحد

إدارة السوق

الإعلانات، المراجعة، المستخدمون، التصنيفات، المظهر وسياسة النشر.

إدارة المتجر

المنتجات، الطلبات، الألعاب، الأكواد الرقمية، كروت الشحن والحزم الإعلانية.

المتاجر والبنرات والأزرار

قسم مخصص لإكمال أدوات التحكم وربطها بالجداول وواجهة العملاء.

القناة الإخبارية

إدارة الأخبار والصور والتصنيفات والنشر بعد تجهيز مصدر الأخبار وربطه بالواجهة.

الذكاء الاصطناعي

إعدادات المساعد ومزود الخدمة. مفتاح API يجب أن يبقى في الخادم وليس في المتصفح.

المحافظ والمدفوعات

متابعة تصميم سجل مالي آمن، دون تعديل أرصدة مباشرة من الواجهة.

مهم: هذه النسخة تجمع اللوحتين الموجودتين ولا تحذف وظائفهما. الأقسام الجديدة ظاهرة كمناطق تجهيز؛ لن أوهمك بأنها متصلة بقاعدة البيانات قبل معرفة جداولها وسياساتها وإضافة واجهات الموقع المقابلة.

إدارة المتاجر والبائعين

لم أجد في الملفات الحالية صفحة CRUD مؤكدة لإدارة جدول المتاجر المعتمد في واجهة العملاء. لا أضيف عمليات كتابة إلى جدول غير معروف حتى لا تتضرر بياناتك.

المطلوب للربط: اسم جدول المتاجر، أسماء أعمدته، وسياسات RLS، وحالات اعتماد المتجر.

إدارة البنرات

هذه الصفحة جاهزة كموقع ضمن لوحة التحكم، لكن لم يتم ربطها بجدول بنرات لأن مخطط قاعدة البيانات الحالي لم يُتحقق منه.

ستدعم بعد الربط: صورة سطح المكتب والجوال، العنوان، الرابط، ترتيب العرض، تاريخ البداية والنهاية، التفعيل والمعاينة.

إدارة الأزرار والروابط

لن أغيّر وجهة أي زر في الموقع تلقائياً. يلزم تحديد مفاتيح الأزرار الحالية وربطها بإعدادات محفوظة يقرأها الموقع.

ستدعم: نص الزر، الرابط، مكان الظهور، إظهار/إخفاء، والترتيب.

القناة الإخبارية للقيمنق

تفعيل القناة فعلياً يحتاج مصدر أخبار موثوقاً أو إدخالاً يدوياً، وجدول أخبار، وربط قسم الأخبار في واجهة الموقع. لا أضع أخباراً وهمية أو أفعّل مصدراً غير محدد.

ستدعم: كتابة الخبر، الصورة، المصدر، التصنيف، تاريخ النشر، مسودة/منشور، تثبيت الخبر وإيقافه.

إعدادات الذكاء الاصطناعي

واجهة الإدارة لا تكفي لتفعيل المساعد وحدها. يلزم تحديد مزود الذكاء الاصطناعي وإنشاء API route أو Edge Function آمنة. لا تضع مفتاح API في HTML أو Supabase المتاح للعميل.

ستدعم: تشغيل/إيقاف المساعد، رسالة الترحيب، حدود الاستخدام، اختيار النموذج، ومؤشرات الاستهلاك. حفظ المفتاح يتم في إعدادات الخادم فقط.

المحافظ والمدفوعات

لن يتم إنشاء أو تعديل أرصدة فعلية من المتصفح. المحافظ تحتاج جداول دفتر أستاذ غير قابل للتلاعب، وعمليات ذرية في قاعدة البيانات، والتحقق من webhooks مزود الدفع.

ستدعم: أرصدة معلقة ومتاحة، الإيداعات، السحوبات، عمولة المنصة، التسويات وسجل الحركات بعد اعتماد مخططها وربط مزود الدفع.

العملاء والصلاحيات

يمكن متابعة المستخدمين من صفحة إدارة السوق الحالية. إدارة صلاحيات الموظفين تتطلب جدول صلاحيات موثوقاً وسياسات RLS تمنع المستخدم من ترقية نفسه.

التقارير

التقارير المالية والمبيعات تحتاج توحيد مصادر الطلبات والمدفوعات أولاً؛ لن أعرض أرقاماً تقديرية على أنها بيانات حقيقية.

الإعدادات العامة

المظهر وسياسة النشر موجودان حالياً في إدارة السوق. إعدادات البنرات والأزرار والأخبار والمساعد ستضاف بعد تجهيز جداولها وواجهاتها.
